# ブログタグ体系

## 構造

タグは2つのレイヤーに分けます。

- **第1層**: 記事の大分類
- **第2層**: いずれか1つの第1層に所属する下位分類

## 第1層

第1層は以下の7種のみです。

- Tech
- Current Affairs
- Creative
- Entertainment
- Gadget
- Trivialities
- Automotive

## 第2層

第2層のタグは、必ずいずれかの第1層に所属させます。
現在36件で、定義は `data/tagset.toml` にあります。

## タグセットの管理

タグセットは以下の2ファイルで管理します。形式の選定理由は
`docs/architectural-decision.md` の ADR-0003 を参照してください。

| ファイル | 役割 | 編集方法 |
|---|---|---|
| `data/tagset.toml` | 第1層・第2層の定義と所属関係 | 手動 |
| `data/tag-vectors.json` | 第2層タグのベクター値 | スクリプトで生成 |

### `data/tagset.toml`

第1層は `[[layer1]]`、第2層は `[[layer2]]` で記述します。
第2層の `parent` には、所属する第1層の `name` を1つだけ指定します。

```toml
schema_version = 1

[[layer1]]
name = "Tech"
description = "ソフトウェア、クラウド、AI、開発ツールなど技術全般。"

[[layer2]]
name = "Generative AI"
parent = "Tech"
description = "生成AIモデルとその活用。LLM、画像生成、プロンプト設計。"
```

タグを追加するときは `[[layer2]]` のブロックを書き足すだけです。
ベクター値はこのファイルには書きません。
`name` は英語、`description` は日本語で記述します。

### `data/tag-vectors.json`

第2層タグごとのベクター値を保持します。手では編集しません。

```json
{
  "schema_version": 2,
  "model": "voyage-4",
  "dim": 1024,
  "input_type": "document",
  "vector_source": "tag_name",
  "normalized": true,
  "updated": "2026-08-31",
  "tags": {
    "Generative AI": {
      "article_count": 49,
      "vector": [0.0132, -0.0451]
    }
  }
}
```

`vector` は実際には `dim` で示した要素数の配列です。上記は例のため省略しています。

`vector` は**タグ名そのものを埋め込んだ値**です。記事の内容は参照しません。
`article_count` は参考値で、記事を数えているだけです。ベクターには使いません。

そのため記事を追加・改稿してもベクターは変わらず、
再算出が必要になるのは `tagset.toml` を編集したときだけです。
記事0件のタグでもベクターを持てるため、新設したタグを直ちに推薦候補にできます。

`vector_source` は算出方式を示します。`schema_version` 1 は記事の
centroid を保持していた旧方式で、現在は使いません。
`model` と `dim` は、埋め込みモデルを変更した際に
全タグの再算出が必要だと判定するために保持します。
モデルの選定理由と呼び出し方は
`docs/architectural-decision.md` の ADR-0004、
タグ名を採用した理由は ADR-0006 を参照してください。

## ベクター値の算出

算出は `scripts/build-tag-vectors.py` が行います。
`tagset.toml` の第2層タグ名を Voyage AI で埋め込み、
`data/tag-vectors.json` を書き出します。

```bash
python3 scripts/build-tag-vectors.py            # 算出して書き出す
python3 scripts/build-tag-vectors.py --dry-run  # 対象のみ表示、APIは呼ばない
```

`VOYAGE_API_KEY` を環境変数に設定して実行します。
未設定なら API を呼ぶ前に終了します。キーはコマンドライン引数では受け取りません。
算出はローカルで実行するため、GitHub Actions のシークレットには登録しません。

### 入力

`data/tagset.toml` の第2層タグ名だけです。記事本文は読みません。
`article_count` の集計のためだけに `content/**/index.md` の
frontmatter を走査します。

### 呼び出し

| 項目 | 値 |
|---|---|
| モデル | `voyage-4` |
| `output_dimension` | 1024 |
| `input_type` | `document` |
| `truncation` | `true` |

429 が返った場合は最大6回まで指数バックオフで再試行します。
選定理由と API の詳細は `docs/architectural-decision.md` の ADR-0004 を参照してください。

### 出力

タグ名の埋め込みを L2 正規化した値を `data/tag-vectors.json` に書き出します。
ファイル全体を毎回書き直すため、タグ単位の部分更新はありません。

### 実行のタイミング

`tagset.toml` を編集したときに実行します。
タグの新設・改名・統合・廃止が該当します。記事を書いても実行は不要です。

1回の実行は36タグで16トークン、1秒未満です。
Voyage AI の無料枠200Mトークンに対して無視できる量です。

## タグ推薦のロジック

記事のタグを決めて frontmatter にセットします。手順は
`.claude/commands/article-tag.md` にあります。

1. 対象記事を読み、内容を表す英単語を5つ選ぶ。既存のタグ一覧は参照しない
2. 5語を**半角スペースで連結し、1つの文字列として**埋め込む
3. 各第2層タグのベクターと内積を取る。双方とも長さ1なのでこれがコサイン類似度になる
4. 最も類似度の高い第2層タグと、その親の第1層タグを frontmatter に書き込む。
   第1層を先頭に置く

### タグ名だけで照合できる理由

埋め込みモデルは、Wikipedia や書籍、Web 上の膨大なテキストを事前学習しており、
「どの語がどの文脈で一緒に使われるか」という一般的な言語知識を持っています。
その知識は、意味の近い語が近い座標に並ぶベクトル空間として蓄えられています。

そのため `Cloud` という文字列を渡すだけで、モデルは「空に浮かぶ雲」だけでなく
「IT のクラウドインフラ」という意味合いを含む座標を返します。記事から選んだ
`infrastructure` や `serverless` といった語も、同じ空間の近い位置に来ます。
このブログで `Cloud` タグが過去どう使われてきたかをモデルが知らなくても、
世間一般でそれらが近い概念であるという知識だけで照合が成立します。

タグ名そのものをベクターにできるのは、この事前学習された知識に乗るからです。
記事の centroid が「このブログでの使われ方」を表すのに対し、
タグ名のベクターは「世間一般でのその語の意味」を表します。

裏を返せば、モデルが持っているのは一般的な言語知識だけです。
タグ名が語義から中身を推測できない名前であれば、モデルはこのブログでの
用法を知らないため、正しく照合できません。後述の
「タグ名を決めるときの基準」はこの制約から導かれます。

### 単語の選び方

- 名詞または名詞句とする。動詞・形容詞は使わない
- 記事の主題を表す語を選ぶ。既存のタグ名に寄せない
- 製品名・企業名・人物名・作品名は避け、一般名詞に置き換える

### 5語を連結する理由

5語を1語ずつタグと突き合わせて最も近い組を採る方式は、実測で精度が
30ポイント近く落ちます。1語ずつ見ると残り4語が捨てられ、
「演奏」と「機材」のように複数語の組み合わせでしか表せない意味が
失われるためです。連結して1本のベクターにすると回復します。

## 精度

3つの期間で実測しました。正解は著者が付けた既存のタグです。

| 期間 | 記事数 | 第2層1位 | 上位3以内 | 第1層 |
|---|---:|---:|---:|---:|
| 2026-03〜05 | 73 | 71.2% | 89.0% | 91.8% |
| 2026-04〜06 | 61 | 75.4% | 93.4% | 88.5% |
| 直近（2026-05-29〜08-29） | 50 | 76.0% | 88.0% | 92.0% |

標準誤差は各期間で5〜7ポイントです。
旧方式（記事全文と記事centroidの照合）の実測値は
第2層1位75.0%、上位3以内88.9%で、同水準に収まっています。

セットしたタグをそのまま使うか書き換えるかは著者が判断します。

### 誤りの傾向

- 誤りの半分以上は同じ第1層の中での取り違えで、第1層は当たります
- 記事の題材語がタグ名と字面で近いと、記事の主題と無関係にそのタグが選ばれます。
  タグ名が抽象的で「何にでも中程度に近い」場合も同様に誤って選ばれます
- 既存のどのタグとも類似度が低い記事は、タグ新設の検討対象になります

## タグ名を決めるときの基準

ベクターがタグ名そのものである以上、タグ名の付け方が推薦精度を直接左右します。

- **タグ名がその説明文を言い当てていること。** 語義から中身が推測できない名前
  （連載名、抽象語、形式を指す語）は、無関係な記事を引き寄せます
- **親と意味が重なる広い語を避ける。** 第1層とほぼ同義の語は第2層に置きません
- **他のタグとの類似度は0.85未満に収める。** 全ペアの中央値は0.64前後で、
  0.85以上は明らかな外れ値です。特に親が異なるタグ同士は必ず下回らせます。
  0.80未満の近さは実測上、誤りの原因になっていません
- **同じ親の中での近接は許容する。** 第1層は当たるため実害が小さいためです
- **製品名・企業名・人物名・作品名はタグにしない**

タグを新設・改名したときは、`tag-vectors.json` を再算出したうえで
全ペアの類似度を確認します。

## タグセット調整の記録（2026-08-31）

タグ名ベクターへの移行にあわせ、タグ名が説明文を言い当てていないもの、
記事数が1〜2件で他タグと重複するもの、親をまたいで近接するものを整理しました。

| | 調整前 | 調整後 |
|---|---:|---:|
| 第2層タグ数 | 47 | 36 |
| 最大類似度 | 0.937 | 0.837 |
| 0.85以上のペア | 4 | 0 |
| 0.80以上のペア | 22 | 6 |
| うち親が異なるもの | 10 | 0 |
| 全ペアの平均 | 0.646 | 0.627 |

調整の型は3つです。

- **改名**: 語義から中身が読めない名前を、説明文を言い当てる名前に変えた
- **統合**: 記事が1〜2件で他タグと語義が重なるタグを、より広いタグに寄せた。
  親をまたいで近接していた対も、区別が記事の立場によるものは一本化した
- **廃止**: 記事の性格を他タグで表せるタグを削り、記事を振り分けた

延べ141記事のタグを更新しました。第1層7種と全388記事の
「第1層1つ・第2層1つ」という構成は維持しています。
記事0件のタグはありません。

### 記事タグの原則

- 第1層タグを1つ、第2層タグを1つ持つ
- 第1層タグを先頭に置く
- 第2層タグの親は、その記事の第1層タグと一致する
