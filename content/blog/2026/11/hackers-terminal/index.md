ドラマ『VIVANT』シーズン2は最終回を残すのみとなり、個人的に盛り上がっております。中でも凄腕ハッカーのBlue@walkerは、エンジニア界隈でも人気のようです。

そこで、ハッカー風ターミナルを表示する設定を自分でも作ってみました。

## 意外にちゃんと作られているBlue@walkerのターミナル

シーンによっては、Blue@walkerが`$ssh bluewalker[Enter]`と打っただけで「ハッキングできました」と言うなど、噴飯ものの表現もあり、ネタにされていました。しかし、Blue@walkerが使う画面をよく見ると、意外にしっかり作り込まれています。

画面は、開発ツールのAndroid Studioと、おそらく独自に作った表示を合成したもので、独自の表示にはARP偽装やBGP乗っ取りのスクリプトらしきものが流れています。Pythonのコードには、劇中の進行に合わせたかのようなコメントまで書かれています。エディタには、暗号化メッセージツールSignalのコードだったり、既知の脆弱性に関連すると思われるコードだったりが開かれており、なにか良からぬ取り組みを思わせます。プロセスの表示にはbashtopが使われています。

IPアドレスにはプライベートアドレスを使い、MACアドレスも明らかに連番と分かるダミーにするなど、プライバシーへの配慮もうかがえます。SSHの場面は笑ってしまいましたが、画面そのものはそれなりに作られています。



## 設計方針

偽のビルドログやダウンロード進捗を延々と流す`genact`や、映画『マトリックス』風の画面を表示する`cmatrix`といったツールを使えば、それらしいターミナル画面は作れます。しかし今回は、自分にとって意味のある情報を表示したいと考え、次の方針を立てました。

- 意味のない表示はしない
- 画面分割はWezTermの機能で行う
- ウィンドウは2つ使う
- シェルコマンド1つで起動できる
- 管理者権限は使わない

ウィンドウを2つに分けたのは、画面いっぱいに表示しつつ、後からレイアウトを変えられる余地を残すためです。画面構成は次のとおりです。

```text
  ウィンドウ 1（監視）                      ウィンドウ 2（株価・ニュース）
  ┌──────────────────┬──────────────────┐   ┌──────────────────┬──────────────────┐
  │ btm              │ gping            │   │ tickrs (summary) │ sysnews          │
  │                  ├──────────────────┤   │                  │                  │
  ├──────────────────┤ wtfutil          │   │                  │                  │
  │ macmon           │                  │   │                  │                  │
  └──────────────────┴──────────────────┘   └──────────────────┴──────────────────┘
```

## ウィンドウ1の説明
ウィンドウ1は主にシステム関連情報を表示します。
### btm

btmは、Rustで書かれたターミナル向けのシステムモニターです（プロジェクト名はbottom）。topやhtopと同じ系統のツールで、使用量の推移をグラフで表示できます。

CPU・メモリ（キャッシュメモリを含む）・温度・プロセス・ディスク・ネットワーク帯域を1つの画面にまとめて表示するので、資源の使用量と、それを使っているプロセスを見比べられます。Mac全体の負荷を一目でつかめる、ウィンドウ1の中心となる表示です。

### macmon

macmonは、Apple Silicon搭載のMac向けのモニターツールで、消費電力・温度・GPUの状態を表示します。btmが見せるのはOSから見た資源の使用量で、macmonが見せるのはチップそのものの状態です。

同じ情報はmacOS標準のpowermetricsでも取れますが、こちらは管理者権限が必要です。macmonはsudoなしで動くため、常に表示しておけます。btmと見比べれば、CPUの負荷が電力や温度にどう表れているかを確かめられます。

### gping

gpingは、pingの応答時間をグラフで表示するツールです。複数の宛先に同時にpingを打ち、結果を1つのグラフに重ねて描けます。

宛先は、自宅のルーター（デフォルトゲートウェイ）と、Cloudflareの公開DNSサーバーである1.1.1.1の2か所です。通信が遅い、あるいは途切れたと感じたときは、2つの応答を比べれば原因のある場所を見分けられます。ルーターへの応答も乱れていれば原因は自宅内（ルーターやLAN）に、ルーターへの応答は安定していて1.1.1.1だけが乱れていれば自宅の外にあります。直近10分間の推移がグラフに残るので、少し前に起きた遅延や途切れにも後から気づけます。

### wtfutil

wtfutil（WTF）は、ターミナル上にダッシュボードを作るツールです。天気・時計・Hacker Newsなどのモジュールが用意されていて、表示したいものを選んで1つの画面に並べられます。

ここには、システム監視以外で日頃確かめたい情報を集めました。東京の天気に加えて、東京・ニューヨーク・ロンドン・ロサンゼルスの現在時刻を表示しています。ウィンドウ2では米国株の値動きや海外のニュースを見るので、現地がいま何時かが分かれば、市場が開いている時間かどうかや、ニュースがいつ出たものかの見当がつきます。

グローバルIPアドレスと回線事業者も表示しています。VPNを経由しているか、どの回線から接続しているかがすぐ分かるので、gpingで通信の乱れに気づいたときの手がかりにもなります。バッテリーの残量と残り時間は、macmonの消費電力と合わせて見ると、負荷がバッテリーの減り方にどう響くかが分かります。Hacker Newsの見出しは、ウィンドウ2の時事ニュースでは拾いきれない技術系の話題を補います。

## ウィンドウ2の説明

ウィンドウ2は株価とニュースを表示します。ウィンドウ1がこのMacと回線の状態を見せるのに対し、こちらは世の中の動きを見せます。

### tickrs

tickrsは、ターミナルで株価のチャートを表示するツールで、データはYahoo! Financeから取得します。Apple・Amazon・IBM・Palantir・Tesla・Alphabetの6銘柄の値動きを、1銘柄数行の要約表示で並べています。銘柄はあくまでサンプルで、エンジニアが興味を持ちそうなものを適当に選びました。

ブラウザや証券会社のアプリを開かなくても、注目している銘柄の動きを目の端で追えます。ハッカー風の画面に流れる数字が架空のものではなく実際の相場であることも、意味のない表示はしないという今回の方針に合っています。

### sysnews

sysnewsは自作のスクリプトで、BBCとNYT、ついでにNHKとYahoo!ニュースの新着の見出しを、時刻順に流し続けます。日本のメディアの偏向具合が酷いので、海外の報道もあわせてウォッチしておきたいと考えました。国内と海外のメディアを並べておけば、同じ時間帯に国内外で何が起きているかを一覧できます。


英語の見出しの翻訳と、私の関心事に合う見出しの強調にはClaude Codeを使っています。APIではなく、サブスクリプションで利用しているClaude Codeを呼び出す形にしています。モデルは軽量のHaikuを指定しています。

これで、海外のニュースも日本語で追えます。関心事に合う見出しは★付きの黄色で強調されるので、流れてくる見出しの中から自分に関係のあるものを見落としにくくなります。

見出しをクリックするとブラウザで記事が開き、あとから履歴を選んで開いたり、org-roamに保存したりもできます。見出しを眺めるだけで終わらず、気になった記事へすぐたどり着けます。

### WezTermの制御

ウィンドウとペインの組み立てには、WezTermに付属する `wezterm cli` を使っています。起動中のWezTermを外から操作するコマンドで、シェルスクリプトから新しいウィンドウを開いたり、ペインを分割したりできます。起動スクリプトsysmonのうち、2つのウィンドウを組み立てる部分は次のとおりです。

```bash,name=sysmon
# ウィンドウ 1: 監視（左 btm / macmon、右 gping / wtfutil）
P=$(wezterm cli spawn --new-window -- \
  gping -n "$PING_INTERVAL" -b "$PING_WINDOW" "${ping_targets[@]}")
B=$(wezterm cli split-pane --pane-id "$P" --left --percent 50 -- \
  btm --enable_gpu --theme nord --enable_cache_memory)
wezterm cli split-pane --pane-id "$B" --bottom --percent 45 -- macmon >/dev/null
wezterm cli split-pane --pane-id "$P" --bottom --percent "$WTF_PERCENT" -- \
  wtfutil --config="$WTF_CONFIG" >/dev/null

# ウィンドウ 2: 株価（左。右上のヘルプ表示は隠す）とニュース（右）
T=$(wezterm cli spawn --new-window -- \
  tickrs --summary -s "$WATCHLIST" -i "$STOCK_INTERVAL" --hide-help)
wezterm cli split-pane --pane-id "$T" --right --percent 50 -- \
  sysnews -i "$NEWS_INTERVAL" >/dev/null
```

`wezterm cli spawn --new-window` は、新しいウィンドウを開いて指定したコマンドを起動し、そのペインのIDを出力します。`wezterm cli split-pane` は、`--pane-id` で指定したペインを `--left` や `--bottom` の方向に分割し、新しいペインの大きさを `--percent` の割合で決めます。分割したペインをさらに分割するときのために、返ってきたIDを変数に受け取っておきます。ウィンドウ1では、gpingのペイン（P）を左に分割してbtmを置き、btmのペイン（B）を下に分割してmacmonを、gpingのペインを下に分割してwtfutilを置いています。この先使わないIDは `/dev/null` に捨てています。

ただし、`wezterm cli` ではウィンドウの位置や大きさを指定できません。2つのウィンドウを画面のどこに置くかは、起動したあとに手で調整しています。

### Claude Codeの呼び出し

sysnewsの要は、Claude Codeの `claude -p`（非対話モード）を、翻訳と判定を受け持つ部品として呼び出しているところです。新しく取得した見出しをまとめてJSONで渡し、見出しごとに日本語訳と、関心事に当たるかどうかの判定を返してもらいます。

```python,name=sysnews
cmd = [
    "claude", "-p",
    "--setting-sources", "",
    "--tools", "",
    "--no-session-persistence",
    "--model", CLAUDE_MODEL,
    "--output-format", "json",
    "--json-schema", json.dumps(SCHEMA),
    "--system-prompt", system_prompt(interests),
    "--", json.dumps(payload, ensure_ascii=False),
]
```

ポイントは、`--json-schema` で出力の形を決めていることです。見出しごとに、日本語の見出し（`ja`）、概要の訳（`desc_ja`）、関心事に当たるか（`hit`）、当たる理由（`why`）を返すようスキーマで指定しているので、返ってきた結果をそのままプログラムで扱えます。翻訳と判定を1回の呼び出しで済ませ、見出しもまとめて渡すので、呼び出しの回数も抑えられます。また、`--tools ""` と `--setting-sources ""` でツールも手元の設定も使わず、`--no-session-persistence` で会話の履歴も残しません。毎回まっさらな状態で、決まった仕事だけをさせる使い方です。

関心事は `interests.md` に自由な文章で書いておき、その内容をシステムプロンプトに埋め込んでいます。

```python,name=sysnews
if interests:
    p += (
        "- hit: 見出しと概要が、下の「注目する内容」のどれかに当てはまれば true。"
        "はっきり関係するものだけを true にし、迷うものは false にする。\n"
        "- why: hit が true のとき、どの項目に当たるかを 15 字以内の日本語で。"
        "false なら空文字。\n\n"
        f"注目する内容:\n{interests}\n"
    )
```

キーワードの一致で拾うのではなく、見出しと概要の意味からLLMが判断するので、関心事に書いた言葉が見出しに含まれていなくても、関係する記事を拾えます。一方で、何でも強調されてしまっては意味がありません。「迷うものはfalseにする」と指示して、はっきり関係するものだけに絞っています。

見出しをクリックするとブラウザが開くのは、OSC 8というエスケープシーケンスを使っているためです。OSC 8は、ターミナルへ表示する文字列にリンク先のURLを埋め込む仕組みです。WezTermなど対応しているターミナルでは、表示した文字列がそのままクリックできるリンクになります。

```python,name=sysnews
def link(url: str, text: str) -> str:
    """OSC 8 ハイパーリンク"""
    return f"\033]8;;{url}\033\\{text}\033]8;;\033\\"
```

表示した見出しは履歴としてファイルに残しておき、`p` キーでfzfの選択画面を開けるようにしています。プレビュー欄で概要（英語の記事は訳と原文）を確かめてから、Enterを押すとブラウザで開き、Ctrl-Bを押すとEmacsのノート管理パッケージorg-roamに保存できます。保存すると記事1件につき1つのノードを作り、記事のURLと概要を書き込みます。同じURLのノードがすでにあれば、重ねては作りません。流れていった見出しにも、あとから戻れます。

Claude Codeの呼び出しに失敗したときは、翻訳と強調をせず、元の見出しのまま表示を続けます。

## まとめ

見た目のそれらしさだけなら、genactやcmatrixで十分です。今回は「意味のない表示はしない」を方針に、既存のターミナルツールと自作のスクリプトを組み合わせて、ハッカー風の画面を作りました。

ウィンドウ1ではこのMacと回線の状態を、ウィンドウ2では株価とニュースという世の中の動きを表示します。どのツールも管理者権限なしで動き、`wezterm cli` で組み立てているので、シェルコマンド1つで2つのウィンドウがそろいます。sysnewsではClaude Codeを翻訳と判定の部品として使い、海外のニュースを日本語で追いながら、関心のある見出しを見落とさないようにしました。

画面に流れているのは、作り物のログではなく、実際の数値と見出しです。設定とスクリプトはGistで公開しているので、表示するツールを差し替えて、自分にとって意味のある画面に組み替えてみてください。
